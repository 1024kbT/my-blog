# 附录：AI 应用开发的资料、练习与项目清单

主线文章解决“学什么”和“怎么学”，附录解决“之后怎么继续补”。如果没有附录，路线图很容易变成看过一次就忘掉的文章。

## 一、练习顺序建议

我会按这个顺序做练习，而不是东看一点西做一点：

1. 做一个最小 AI 工具
2. 给它补 Prompt 模板
3. 补多轮对话或历史记录
4. 做一次部署
5. 写一篇复盘
6. 再开始做第二个项目

这样每一轮练习都会留下真正能复用的资产。

## 二、适合反复练手的项目清单

### 入门项目

- 摘要助手
- 改写助手
- 待办清单生成器
- Prompt 测试页

### 进阶项目

- 文档问答
- AI 写作助手
- 多轮对话工具
- 简单知识库问答

### 高级方向

- 多模型切换工作台
- 带日志和缓存的 AI 服务层
- 带工具调用的任务流系统
- 带权限边界的内部 AI 应用

## 三、每做完一个项目，最好补这四类文档

| 文档类型 | 用处 |
| --- | --- |
| 功能说明 | 让未来的自己知道它解决什么问题 |
| Prompt 记录 | 保留哪些模板有效、哪些无效 |
| 踩坑记录 | 防止下次重复犯错 |
| 架构摘要 | 方便后面继续扩展 |

## 四、复盘时别只复盘“模型回答好不好”

我更建议从四个角度看：

- **产品**：用户会不会再回来
- **工程**：结构清不清楚，好不好继续改
- **Prompt**：是否足够稳定
- **系统**：有没有已经暴露出扩展问题

## 五、适合长期积累的个人模板

如果你真的想把博客当知识库，我很建议把下面这些模板固定下来：

- 学习路线模板
- 项目复盘模板
- Prompt 模板
- 错误排查模板
- 架构摘要模板

## 七、附录真正的作用

主线文章像地图，附录更像工具箱。地图告诉你方向，工具箱保证你下次回来还能继续动手。

如果以后你继续往这套专题里加内容，我建议优先补两种：
