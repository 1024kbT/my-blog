# 初中级进阶：把 AI Demo 做成真正可用的小产品

到了这一层，重点已经不再是“我能不能调通接口”，而是“别人用起来会不会觉得这是个产品，而不是一个半成品页面”。

## 这一阶段要跨过哪道坎

我会把核心变化总结成一句话：

**从单次调用，进入连续使用。**

这意味着你要开始关心：

- 用户会不会反复使用
- 输入输出是不是可管理
- 错误状态是不是可理解
- 上下文是不是会失控

## 四个必须补上的能力

### 1. 多轮对话和上下文管理

从这一阶段开始，单轮请求已经不够了。你需要知道：

- 哪些上下文该保留
- 哪些历史消息该裁剪
- 怎么避免上下文越来越乱

### 2. 稳定的提示词模板

提示词不能只靠手动微调。更稳的做法是把它分成几层：

- 系统角色
- 用户输入
- 输出格式
- 约束条件

当提示词开始模板化，应用才有复用和维护的可能。

### 3. 产品级交互

至少要把下面这些状态做好：

- 空态
- 加载中
- 出错提示
- 重试入口
- 历史记录或结果回看

很多 AI Demo 之所以像“实验品”，不是模型不行，而是交互没收好。

### 4. 可访问的部署

这个阶段应该至少做出一个别人能打开的版本。哪怕只是 GitHub Pages、Vercel 或一个简单服务，也比只在本地跑更接近真实使用场景。

## 适合这个阶段做的项目

我会优先做这些：

- 文档问答
- Prompt 工作台
- AI 写作助手
- 带历史记录的多轮对话页

判断标准不是“最酷”，而是是否覆盖了：

- 接口调用
- 状态管理
- Prompt 模板
- 页面交互
- 基础部署

## 这个阶段最值得积累什么

### 一套你自己的模板

包括：

- Prompt 模板
- 错误提示模板
- 页面状态模板
- 调用封装模板

这类资产以后会反复复用，远比只做一个孤立项目值钱。

### 一份自己的失败清单

我很建议在这个阶段写一份“我最常犯的五个错误”，比如：

- Prompt 约束不清
- 上下文裁剪太粗
- 错误提示只有一句“请求失败”
- 没有结果复用能力
- 本地能跑，部署就炸

## 什么时候算进入高级阶段

当你开始主动思考下面这些问题时，就说明你已经在往高级开发走：

- 模型切换怎么抽象
- 调用成本怎么控制
- 日志怎么记录
- 数据怎么存
- 工具调用怎么设计
- 工作流怎么拆
