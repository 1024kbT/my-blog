# 做一个可维护的前端博客系统，我会先守住什么

如果只是做一个好看的首页，前端博客其实不难。难的是让它半年后、一年后、内容翻几倍之后，依然不难维护。

## 我不会先追的东西

如果目标是长期写作，我不会一开始就把精力放在：

- 很重的动画
- 复杂的个性化交互
- 过多的首页装饰
- 很深的构建链改造

这些都不是没价值，只是它们不该先于内容结构。

## 我会先守住四件事

### 1. 文章的文件组织

文章路径要一眼能看懂。  
比如：

- `posts/essay`
- `posts/architecture`
- `posts/engineering`

这不是炫技，但它决定了后续归档、标签和专题页会不会轻松。

### 2. 页面角色清晰

首页、文章页、标签页、归档页、数据页，它们各自应该干什么，最好从一开始就分清：

- 首页负责第一印象
- 文章页负责阅读体验
- 标签页负责聚合
- 归档页负责时间线
- 数据页负责站点自我说明

### 3. 第三方集成集中配置

评论、统计、搜索之类的服务，最好都能在一个文件里改。  
这样你以后迁移服务时，不用在组件里到处翻。

### 4. 构建和部署路径稳定

博客这类项目最怕的是：

- 本地能跑
- 线上路径炸掉
- 改一点配置就重新踩坑

所以像 `base`、部署 workflow 这些地方，宁愿简单，也要稳定。

## 博客不是一次性活动页

做长期博客，思路应该更像在做一个“低成本持续更新的内容系统”，而不是一个只用来惊艳第一次访问的页面。

你越早承认这一点，后面的维护体验通常越好。
